Chapter 32 — Advanced Structures: Segment Tree, Fenwick Tree & Union-Find

Volume 1 — Computer Science Foundations · Contents · ← Chapter 31 — Hash Tables & Graphs · Next → Chapter 33 — Sorting, Searching & Binary Search

Concept

Range queries (segment/Fenwick) and dynamic connectivity (union-find with path compression + union by rank).

In one sentence: segment and Fenwick trees precompute partial answers over ranges so that "sum/min of a[l..r]" and "change a[i]" both take O(log n), and union-find keeps track of which items are in the same group while groups keep merging.

Mental model.

  • Segment tree — a tournament bracket. Each match stores the winner (min) or total (sum) of its half. To answer "who's best among players 3–9?" you combine a few bracket nodes instead of rescanning everyone.
  • Fenwick tree — a clever bookkeeper who keeps running totals of cleverly sized blocks (1, 2, 4, 8 … items), chosen by the lowest set bit of the index.
  • Union-find — clubs where each member points to a "representative". Merging two clubs just makes one representative report to the other. "Are we in the same club?" = "do we have the same representative?"

Union-find (disjoint set union, DSU)

OperationMeaning
find(x)return the representative (root) of x's set
union(a, b)merge the sets containing a and b
connected(a, b)find(a) == find(b)

Two optimizations — use both

  1. 1. Union by rank/size — attach the shorter tree under the taller one, so trees stay shallow (height ≤ log n).
  2. 2. Path compression — during find, point every visited node directly at the root, so future finds are instant.

Together: amortized O(α(n)) per operation, where α is the inverse Ackermann function — ≤ 4 for any n that fits in the universe. "Near O(1)".

Uses: Kruskal's minimum spanning tree, cycle detection in undirected graphs, grouping accounts/images/pixels, network connectivity, percolation.

Example

python 
class Fenwick:
    """1-indexed binary indexed tree for prefix sums."""
    def __init__(self, n):
        self.n, self.t = n, [0] * (n + 1)

    def add(self, i, delta):            # a[i] += delta, O(log n)
        while i <= self.n:
            self.t[i] += delta
            i += i & -i                 # jump to the next node covering i

    def prefix(self, i):                # a[1] + … + a[i], O(log n)
        s = 0
        while i > 0:
            s += self.t[i]
            i -= i & -i                 # drop the lowest set bit
        return s

    def range_sum(self, l, r):
        return self.prefix(r) - self.prefix(l - 1)

a = [5, 2, 6, 1, 3, 4, 8, 7]
fw = Fenwick(len(a))
for i, x in enumerate(a, 1):
    fw.add(i, x)
print(fw.range_sum(3, 6))               # 6+1+3+4 = 14
fw.add(4, 10)                           # a[4] becomes 11
print(fw.range_sum(3, 6))               # 24
python 
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:           # path compression
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                         # already connected → a cycle if a–b is an edge
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra                     # union by size
        self.size[ra] += self.size[rb]
        return True

edges = [(0, 1), (1, 2), (3, 4), (2, 0)]
d = DSU(5)
for u, v in edges:
    if not d.union(u, v):
        print("cycle via", (u, v))              # cycle via (2, 0)
print(len({d.find(i) for i in range(5)}))       # 2 components

Exercises

  1. 1. Build a Fenwick tree for prefix sums.
    Solution See Fenwick above. Build in O(n) instead of n·log n: copy the array, then for each i add t[i] into t[i + (i & -i)] if in range. Test against sum(a[l-1:r]) after random updates.
  2. 2. Implement union-find and detect a cycle in a graph.
    Solution For each undirected edge (u, v), if find(u) == find(v) they're already connected, so the edge closes a cycle; otherwise union them. O(E·α(V)) — the same loop is the core of Kruskal's MST.
  3. 3. Why can't a Fenwick tree answer range minimum queries with updates?
    Solution It answers ranges as prefix(r) − prefix(l−1), which needs an inverse operation. Subtraction undoes addition, but nothing "un-mins" a minimum. Use a segment tree.

Interview

  1. 1. "When do you need a Fenwick tree?"
    Answer When you need prefix or range sums (or any invertible, associative operation like XOR) and point updates, both fast. A plain prefix-sum array is O(1) query but O(n) update. A Fenwick tree makes both O(log n) with ~10 lines of code and n memory. For min/max or complex range updates, use a segment tree.
  2. 2. "Why is union-find near-O(1) amortized?"
    Answer Union by rank keeps trees O(log n) tall. Path compression flattens every path it walks, so repeated finds become one hop. Tarjan proved the combination costs O(α(n)) amortized per operation, where the inverse Ackermann function α(n) ≤ 4 for all practical n.
