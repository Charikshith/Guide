Chapter 33 — Sorting, Searching & Binary Search

Volume 1 — Computer Science Foundations · Contents · ← Chapter 32 — Advanced Structures: Segment Tree, Fenwick Tree & Union-Find · Next → Chapter 34 — Graph Algorithms: DFS, BFS, Topological Sort & Backtracking

Concept

Quicksort/mergesort/heapsort, stability, and binary search on sorted data and monotonic predicates.

In one sentence: sorting puts data in order so that later questions become cheap, and binary search answers "where does this go?" or "what's the smallest value that works?" by halving the candidates each step.

Mental model — a phone book. Nobody reads a phone book from page 1. You open it in the middle, see "M", and throw away half. Twenty halvings find any name among a million. Binary search works on anything where the answer flips once from "no" to "yes" — not just sorted arrays.

The main sorts

Counting / radix sortO(n + k)O(n + k)O(n + k)O(n + k)yesintegers or keys in a small range; not comparison-based

Comparison sorts can't beat Ω(n log n) in the worst case: there are n! orderings, and each comparison gives one bit, so you need log₂(n!) ≈ n log n comparisons.

Stability — a stable sort keeps equal elements in their original order. It matters when you sort by several keys: sort by name, then stably by department, and names stay alphabetical inside each department.

Binary search patterns

PatternQuestionTool
Exact matchis x in the sorted array?bisect_left + check

Search-on-the-answer examples: minimum eating speed to finish in h hours, minimum ship capacity, first bad version, smallest k that makes a model's latency acceptable.

Example

python 
from bisect import bisect_left, bisect_right
import math

xs = sorted([5, 1, 4, 1, 3])                   # Timsort → [1, 1, 3, 4, 5]
print(bisect_left(xs, 1), bisect_right(xs, 1))  # 0 2 — the range of 1s is [0, 2)

people = [("ann", "eng"), ("bob", "ops"), ("cat", "eng"), ("dan", "ops")]
by_dept = sorted(sorted(people), key=lambda p: p[1])   # stable → names stay sorted per dept
print(by_dept)   # [('ann','eng'), ('cat','eng'), ('bob','ops'), ('dan','ops')]

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:                 # <= keeps it stable
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

import random
def quicksort(a, lo=0, hi=None):
    hi = len(a) - 1 if hi is None else hi
    if lo >= hi:
        return a
    p = random.randint(lo, hi)                  # random pivot avoids O(n²) on sorted input
    a[p], a[hi] = a[hi], a[p]
    pivot, i = a[hi], lo
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]; i += 1
    a[i], a[hi] = a[hi], a[i]
    quicksort(a, lo, i - 1); quicksort(a, i + 1, hi)
    return a

def first_true(lo, hi, ok):
    """Smallest v in [lo, hi] with ok(v) True; ok must be monotonic."""
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid): hi = mid
        else: lo = mid + 1
    return lo

piles, hours = [3, 6, 7, 11], 8
speed = first_true(1, max(piles), lambda k: sum(math.ceil(p / k) for p in piles) <= hours)
print(speed)                                    # 4 — minimum bananas/hour

Exercises

  1. 1. Implement mergesort and quicksort.
    Solution See above. Test both against sorted() on random arrays, arrays with many duplicates, already-sorted arrays, and reversed arrays. For quicksort on many duplicates, switch to 3-way partitioning (<, =, >) to avoid O(n²).
  2. 2. Use binary search on the answer (e.g., min speed).
    Solution See first_true. Recipe: (1) define ok(v); (2) prove it's monotonic; (3) bound the range [lo, hi]; (4) binary search. Cost: O(log range × cost of ok).
  3. 3. Why does mid = (lo + hi) // 2 never loop forever in first_true, but lo = mid would?
    Solution mid rounds down, so mid < hi whenever lo < hi. Setting hi = mid or lo = mid + 1 always shrinks the range. With lo = mid, when hi = lo + 1, mid == lo and nothing changes.

Interview

  1. 1. "Stable vs unstable sort?"
    Answer A stable sort preserves the original relative order of equal keys; an unstable one may reorder them. Stability lets you sort by multiple keys in passes (secondary key first, then primary) and keeps UI ordering predictable. Merge sort and Timsort are stable; quicksort and heapsort usually aren't.
  2. 2. "Binary search on a predicate — how?"
    Answer If a yes/no function over an ordered range is monotonic — all false, then all true — you can find the boundary in O(log range) evaluations. Keep a half-open [lo, hi), test mid, and move lo or hi so the invariant "the answer is in [lo, hi]" holds. Used for minimum capacity, first failing version, and tuning thresholds.
